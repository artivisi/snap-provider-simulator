First release. Simulates BRI's publicly documented SNAP VA behaviour; not
affiliated with or endorsed by PT Bank Rakyat Indonesia.

## Image

```
docker pull ghcr.io/artivisi/snap-provider-simulator:2026.10
```

linux/amd64 and linux/arm64. Run with `compose.yml` from the repository; see
the README for the required environment variables.

## Changes

- Partner onboarding portal: sign-up, VA prefix, client id and secret, key
  pair generation or public key upload, partner endpoint with test connection,
  token TTL, diagnostic mode, onboarding checklist, reset.
- B2B access token (SHA256withRSA) and service-call checks: bearer token,
  mandatory headers, timestamp skew, HMAC-SHA512, `X-EXTERNAL-ID` per day.
- Diagnostic mode for failed signatures: expected string-to-sign, body hashes
  and a hint naming the mistake.
- Bank-hosted VA: create, update, inquiry, delete, inquiry status.
- Bank-to-partner inquiry and payment (BRIVA Online), payment of bank-hosted
  VAs, resend with the same `X-EXTERNAL-ID`.
- Error injection: timeout after processing, slow response, HTTP 500/502/503,
  invalid signature, late or dropped notification.
- Daily statement CSV and reconciliation scenario seeder.
- Exchange log of every inbound and outbound call.
- Operator admin: partners, checklist progress, disable, reset, delete.

## Upgrade notes

- None (first release).

## Known limitations

- QRIS, VA `update-status` (29) and `report` (35) are not implemented.
- Only closed single-payment VAs (`virtualAccountTrxType` absent or `C`).
- Test tool: no login lockout, rate limiting or field encryption.
